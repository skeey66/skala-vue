# 모닥불

강의 Hands on 9개를 차례로 실습하면서, 그 실습본을 버리지 않고 계속 이어 붙여 만든 캠핑 날씨
서비스입니다. 오늘 어느 지역이 캠핑하기 좋은지 100점으로 매기고, 그 조건에 맞는 야영장을 찾아 줍니다.

https://skala-vue-three-navy.vercel.app

비가 오면 불이 약해지고, 바람이 불면 위태롭고, 공기가 나쁘면 오래 못 앉아 있습니다.
캠핑하기 좋은 조건과 불이 잘 타는 조건이 거의 같아서 지수 이름을 모닥불로 지었습니다.

단계마다 네 가지를 적었습니다. 무엇을 만들었는지, 그게 최종 서비스에 남았는지, 요구사항 밖에서
따로 더한 것, 그리고 막혔던 것.

## Hands on 1 — Project Scaffolding

### 구현 내용

1. `npm create vue@latest` 로 Router, Pinia, ESLint, Prettier 를 함께 넣어 생성
2. `index.html` → `main.js` → `App.vue` 진입 경로 확인, 화면은 SFC 로 작성
3. HMR 과 Vue Devtools 로 상태가 바뀌는 시점을 눈으로 확인

### 최종 서비스 적용 여부

이 프로젝트가 그대로 모닥불이 됐습니다. 단계마다 새 프로젝트를 만들지 않고 하나를 계속 고쳤습니다.

### 개인 추가·변경 내용

1. 강의 트리의 `components/exercise/` 격리 폴더를 두지 않았습니다. 실습본이 그대로 서비스가 될
   것이라 처음부터 실제 부품 자리에 뒀습니다
2. `api` / `composables` / `data` / `stores` 로 폴더를 나눴습니다. 뒤 단계에서 채울 자리를 미리 잡은 것입니다

### 트러블 슈팅

없었습니다.

## Hands on 2 — Weather Mockup

### 구현 내용

1. 목업 배열을 `v-for` 로 그리고 `:key` 에 도시 id 를 줌
2. `v-if` / `v-else` 로 기온에 따라 다른 라벨
3. 검색창을 `v-model` 대신 `:value` + `@input` 으로 엮음
4. 카드 안 버튼에 `@click.stop`, 카드 클릭은 `window.alert` 로 상세

### 최종 서비스 적용 여부

목업 배열은 Hands on 7 에서 API 응답으로 전부 교체됐고, 좌표만 `data/cityList.js` 에 남았습니다.
3곳이던 목록은 전국 17개 시도가 됐습니다.

`@click.stop` 은 야영장 카드의 찜 하트에 그대로 있습니다. 하트를 눌렀을 때 상세가 같이 열리면 안 되니까요.
`window.alert` 상세는 Hands on 5 에서 `router.push` 로 바뀌었습니다.

목업으로 목록을 만드는 방식 자체는 커뮤니티(셰르파 동행, 장비 중고거래) 두 화면으로 넓혔습니다.
글과 신청이 오가려면 서버가 있어야 하는데 프런트만 만드는 과제라 화면까지만 만들고
내용은 `data/communityMock.js` 에 뒀습니다.

> 상태바("{도시}이 선택되었습니다")도 최종 실습본에서 제거했습니다.
> 카드를 눌렀다는 사실을 글로 알려주는 칸인데, 지금은 누른 지역이 지도에서
> 밝게 표시되고 타일에도 테두리가 생겨서 굳이 문장으로 다시 말할 필요가 없습니다.
> 클릭 처리와 `@click.stop` 은 그대로 남아 있습니다.

### 개인 추가·변경 내용

기본 제공은 서울·수원·부산 3곳에 `id` `name` `temp` `status` 네 개 필드였습니다.

1. 도시 7곳 추가: 제주, 강릉, 대관령, 인천, 대구, 광주, 울릉도
2. 필드 6개 추가: `feelsLike` `humidity` `wind` `rainProb` `dust` `updatedAt`
3. 강수확률 60% 이상이면 우산 라벨을 하나 더
4. 기준값을 상수로: `HOT_THRESHOLD`(25), `RAIN_THRESHOLD`(60). 카드 배지와 상단 요약이 같은 값을 봄
5. 상단 요약: "10개 · 평균 22.9°C · 25°C 이상 6곳 · 우산 3곳"

도시 값은 숫자만 채우지 않고 분기를 확인할 수 있게 골랐습니다. 대관령 -2°C 는 음수 기온,
인천 25°C 는 "25도 이상" 경계값을 보려고 넣었습니다.

### 트러블 슈팅

한글 검색창에 `v-model` 을 썼더니 "서울" 을 치는 동안 "ㅅ", "서" 가 안 들어오고 글자가 완성된
뒤에야 들어왔습니다. 한글은 조합 중에도 input 이벤트가 도는데 `v-model` 은 완성된 글자만
올려 보냅니다. `:value` + `@input` 으로 바꿔 해결했습니다.

## Hands on 3 — Weather Composition

### 구현 내용

1. `ref` 로 검색어와 정렬 기준을 상태로
2. `computed` 로 검색 결과, 정렬 목록, 평균 기온을 파생
3. `watch` 와 `watchEffect` 를 나눠 씀. 볼 대상이 분명하면 `watch`, 아니면 `watchEffect`
4. `watch` 의 `onCleanup` 으로 이전 비동기 요청 취소
5. 라이프사이클 훅을 확인하고 DOM 이 필요한 일을 `onMounted` 뒤로
6. watch 가 도는 시점을 화면에서 보려고 로그 패널 제작

### 최종 서비스 적용 여부

computed 체인이 지금도 화면의 뼈대입니다. 캠핑장 찾기는 전국 목록에서 사진 있는 곳을 거르고,
검색어로 거르고, 조건으로 다시 거르는 것이 전부 computed 로 이어집니다.

`watch` 는 주소와 화면 상태를 묶는 데 씁니다. 검색어가 바뀌면 `?q=` 를 갱신하고,
`?district=` 가 바뀌면 그 시군구의 예보와 야영장을 다시 받습니다.

`onMounted` / `onBeforeUnmount` 는 Leaflet, ResizeObserver, IntersectionObserver, 스크롤 잠금처럼
Vue 밖의 것을 붙이고 떼는 자리에 씁니다.

> 반응형 로그 패널은 최종 실습본에서 제거했습니다.
> `watch` / `watchEffect` 가 언제 도는지 화면에서 확인하려고 만든 것인데,
> 캠핑 날씨를 보러 온 사람에게는 필요 없는 화면이라 뺐습니다.
> `console.log` 와 스토어 로그는 남아 있어 동작은 개발자 도구에서 확인할 수 있습니다.

로그만 찍던 watcher 다섯 개도 같이 지웠습니다. 주소를 동기화하는 두 개는 남겼습니다.

### 개인 추가·변경 내용

1. 정렬 기준 `sortKey` 추가 (기본순 / 기온 높은순 / 이름순)
2. `visibleList` — 검색 결과에 정렬까지 적용하는 computed 체인
3. `averageTemp` — 화면에 보이는 도시의 평균 기온
4. `watch(searchQuery)` 에 `onCleanup` 을 붙여 이전 요청 취소
5. 로그 패널 UI

4번은 요구사항에 없는데, 예시 화면 콘솔의 `started` / `completed` 가 궁금해서 만들어 봤습니다.
빠르게 타이핑하면 `started` → `cancelled` 가 이어지다 마지막 입력만 `completed` 까지 갑니다.

### 트러블 슈팅

캠핑장 조건 필터에서 지형·시설 칩이 눌려도 아무 일이 없었습니다. 오류도 안 났습니다.
`flip(terrains, item)` 처럼 ref 를 인자로 넘겼는데 template 에서는 ref 가 자동으로 벗겨져
함수가 받은 건 배열이었습니다. 함수 안의 `.value` 대입이 원본에 닿지 않았던 것입니다.
어느 묶음인지를 문자열로 받게 고쳤습니다.

## Hands on 4 — Weather Component

### 구현 내용

1. 한 파일이던 화면을 `WeatherParent`, `BaseDashboardCard`, `SearchBar`, `WeatherCard` 로 분리
2. 부모가 상태를 들고 `props` 로 내려주고 자식은 `emits` 로 올려 보냄
3. `BaseDashboardCard` 는 내용을 모르게 `<slot>` 으로만 받음
4. `<style scoped>` 로 스타일 격리

### 최종 서비스 적용 여부

`WeatherParent` 만 `RegionsView` 로 이름이 바뀌었고 나머지 셋은 그대로 살아 있습니다.

`BaseDashboardCard` 는 지금 사이트 모든 판의 생김새를 혼자 책임집니다. 직사각형, 위쪽 가는 선,
화면에 들어올 때 한 번 떠오르는 연출까지. 여전히 안에 무엇이 들어오는지는 모릅니다.

부품은 넷에서 열다섯 개가 됐습니다.

### 개인 추가·변경 내용

1. `BonfireGauge` — 지수를 모닥불 그림으로 그리는 SVG. 점수 구간에 따라 불꽃 갈래와 불티 수가 달라짐
2. `CampSheet` — 야영장 상세 드로어. 캠핑장 찾기, 오늘의 추천, 찜, 지역 상세 네 화면이 함께 씀
3. `RegionMap` / `CampMap` — Leaflet 지도. 시도 경계 색칠과 야영장 번호 핀
4. `PageHero` — 화면 맨 위 전면 사진 배너
5. `BaseDashboardCard` 에 IntersectionObserver 로 등장 연출 추가

### 트러블 슈팅

1. `CampSheet` 를 세 화면에 붙였는데 드로어가 조용히 안 열렸습니다. `import` 누락이었는데
   eslint 도 빌드도 통과했습니다. eslint 는 template 안의 미등록 컴포넌트를 잡지 못합니다
2. `BonfireGauge` 를 한 화면에 열일곱 개 띄웠더니 전부 마지막 것의 색이 됐습니다.
   SVG 그라디언트 `id` 가 전부 같아 충돌한 것이라 `useId()` 로 갈랐습니다
3. 주간 그래프 폭이 안 따라왔습니다. `:key` 로 지역을 바꾸면 덩어리가 새로 만들어지는데
   ResizeObserver 를 `onMounted` 에서 한 번만 걸어 떨어져 나간 옛 요소를 보고 있었습니다

## Hands on 5 — Weather Router

### 구현 내용

1. Router 를 붙이고 `App.vue` 에 `<RouterView />` 와 내비게이션 바
2. `/weather/:cityId` 동적 경로를 `route.params` 로 받아 상세를 그림
3. `/:pathMatch(.*)*` Catch-all 을 맨 뒤에 두어 404 처리
4. 모든 라우트를 `() => import()` 로 감싸 화면별 청크로 분리
5. 상세 이동을 `window.alert` 에서 `router.push()` 로

### 최종 서비스 적용 여부

라우트는 열두 개가 됐습니다. 이 단계에서 가장 크게 남은 건 상태를 주소에 싣는 방식입니다.
보기 모드(`?view=`), 야영장 종류(`?type=`), 시군구(`?district=`), 지역(`?region=`), 검색어(`?q=`)가
전부 주소에 들어갑니다. 링크를 그대로 주고받을 수 있고 뒤로 가기가 예상대로 동작합니다.

화면을 합치며 없어진 주소는 리다이렉트로 남겼습니다. `/ranking` 은 `/regions?view=rank` 로 넘어갑니다.

### 개인 추가·변경 내용

1. `/ranking` 화면 추가. 나중에 날씨 화면의 보기 모드로 합침
2. 검색어를 `?q=` 에 유지해 상세에 갔다 돌아와도 남게
3. 404 에 `route.fullPath` 를 함께 표시
4. 없는 도시 코드(`/weather/city_99`)를 상세 화면 안에서 안내

### 트러블 슈팅

첫 화면에서 스크롤을 가로채는 처리를 넣었더니 다른 화면으로 넘어가도 잠긴 채 남았습니다.
SPA 는 페이지를 새로 받지 않으니 `onBeforeUnmount` 에서 직접 풀어야 합니다.

## Hands on 6 — Weather Store

### 구현 내용

1. Pinia 스토어를 `state` / `getters` / `actions` 로 구성
2. 단위 상태를 `configStore` 에 두고 `UnitToggler` 를 내비게이션 바에 배치
3. 인자를 받는 getter 구현 (`isFavorite(id)`)
4. 단위 변환을 `useTemperature` composable 로 분리
5. 관심 목록을 `localStorage` 에 저장

### 최종 서비스 적용 여부

`configStore` 는 실습에서 만든 그대로입니다.

`weatherStore` 는 서비스의 중심이 됐습니다. 17개 지역 응답을 모아 10분 캐시하고, 지역별 야영장과
주간 예보도 여기서 관리합니다. 화면을 오가도 다시 부르지 않습니다.

`favoriteStore` 는 관심 지역에서 야영장 찜으로 바꿨습니다. "강원도를 찜한다"는 말은 잘 안 쓰고,
가고 싶은 캠핑장을 담아 뒀다가 예약하니까요. 야영장은 API 에서 오므로 id 만 저장하면 찜 화면을
열 때마다 전국 목록을 다시 받아야 해서, 화면에 필요한 만큼만 잘라 함께 저장합니다.

`useTemperature` 도 남았습니다. 원본은 항상 섭씨로 두고 그릴 때만 바꿉니다.
25도 이상 같은 판정은 원본으로 해야 단위를 바꿔도 결과가 흔들리지 않습니다.

### 개인 추가·변경 내용

1. `favoriteStore` 추가 — getter `count` / `isFavorite` / `recent`, action `toggle` / `remove` / `clear`
2. `configStore` 에 `unitLabel`, `isFahrenheit` getter 와 `setUnit` action
3. 찜을 세 곳에 연동 — 카드의 하트, 상세 드로어의 버튼, 내비게이션 바의 개수 배지

### 트러블 슈팅

내비게이션 바에 "찜 3" 이 뜨는데 찜 화면은 비어 있었습니다. `localStorage` 에 실습 초반의 옛
id(`city_02`)가 남아 있었고 그 사이 체계가 `sido_11` 로 바뀌어 있었습니다. 배지는 개수만 세고
화면은 그 지역을 못 찾은 것입니다. 불러올 때 없는 id 를 걸러내도록 고쳤습니다.

## Hands on 7 — Weather Axios

### 구현 내용

1. `axios.create` 로 baseURL, timeout, 공통 params 를 한곳에
2. 목업을 걷어내고 OpenWeatherMap 의 현재 날씨와 대기 오염을 실제로 연결
3. `Promise.all` 로 여러 도시를 한꺼번에, 일부 실패를 허용할 곳은 `allSettled`
4. 응답 인터셉터로 오류 처리와 재시도를 한곳에
5. CORS 로 막히는 공공데이터포털은 개발 서버 프록시로 우회

### 최종 서비스 적용 여부

여기서 목업이 빠지면서 캠핑 서비스가 됐습니다. API 는 세 곳입니다.

- OpenWeatherMap — 현재 날씨, 3시간 예보와 강수확률, 대기 오염, 지오코딩
- Open-Meteo — 자외선, 밤 최저기온, 해발고도, 시군구 250곳 예보
- 고캠핑 — 전국 야영장 목록, 반경 야영장, 야영장 사진

지수는 이 값들을 100점으로 옮긴 것입니다. 비 30, 바람 25, 밤 기온 25, 공기 12, 하늘 8.
등급은 활활 / 타닥타닥 / 가물가물 / 연기만.

바람은 평균이 아니라 순간 최대로 봅니다. 밤 기온은 4~14도가 최적이고 26도를 넘으면 2점만 줍니다.
낮이 아니라 밤을 보는 건 캠핑이 그 자리에서 자기 때문입니다.

인터셉터는 `api/retry.js` 하나로 모아 세 API 가 함께 씁니다.

### 개인 추가·변경 내용

1. 캠핑 컨셉으로 전환 — 밤 최저기온을 중심에 놓고 지수를 불의 언어로
2. `useBonfireScore` — 지수, 등급, 오늘 맞는 캠핑 방식, 침낭 등급, 바람 판정을 한곳에
3. 요소별 점수 펼치기 — 합계만 보면 왜 그 점수인지 알 수 없어서 비 30/30, 기온 6/25 처럼 나눠 표시
4. Open-Meteo 좌표 묶음 호출 — 콤마로 이어 붙여 17개 지역을 1콜, 시군구 250곳도 1콜
5. 5일 야간 예보 — `/forecast` 40구간에서 18시부터 다음 날 06시까지를 하루로 접음
6. 시도 → 시군구 드릴다운
7. 전국 야영장 3,096곳을 한 번 받아 브라우저에서 거름 (사진 있는 곳 2,333곳)
8. 조건 필터 — 지역, 지형, 시설, 화로대, 반려동물
9. 한글 부분 검색 — "울ㅅ" 로 울산이, "ㅈㅈ" 처럼 자음만 치면 초성 검색
10. 지오코딩으로 목록에 없는 지역도 좌표를 받아 추가

### 트러블 슈팅

1. 공공데이터포털은 CORS 헤더를 주지 않아 브라우저에서 직접 못 부릅니다. 프록시를 뒀습니다.
   인증키도 Encoding 값을 쓰면 axios 가 한 번 더 인코딩해 실패합니다. Decoding 값을 씁니다
2. Open-Meteo 와 OpenWeatherMap 이 둘 다 `sunrise` 를 주는데 형식이 달라(ISO 문자열 / 초 단위)
   객체를 합칠 때 덮어써졌습니다. 한 곳에서만 받도록 정리했습니다
3. 밤을 접을 때 날짜 키를 `toISOString()` 으로 만들면 안 됩니다. UTC 로 바뀌며 한국 시간
   저녁 18~23시가 전날 칸으로 들어갑니다. 지역 시각의 연·월·일을 직접 조합해야 합니다
4. 시군구에 "바람 17.3" 이 떠서 파 보니 Open-Meteo 는 풍속을 km/h 로 줍니다. 지수 기준은 m/s 라
   3.6배로 읽혀 바람 25점이 통째로 0 이었습니다. `wind_speed_unit: 'ms'` 로 맞췄습니다
5. 고캠핑 `searchList` 는 이름만 훑습니다. "강원" 을 넣으면 이름에 강원이 든 두 곳만 나옵니다.
   지역으로 찾으려면 전체 목록이 필요해 `basedList` 로 한 번 받아 두고 브라우저에서 거릅니다
6. 시군구를 눌러 보다 429 가 났습니다. 고캠핑 일일 한도 초과였고, 한도는 오퍼레이션별로 따로
   걸립니다. 좌표별 캐시와 320ms 디바운스를 넣고, 429 를 잠깐 몰린 것과 하루치가 끝난 것으로
   갈라 앞의 경우만 재시도하게 했습니다

## Hands on 8 — Weather UI Library

### 구현 내용

2. `NConfigProvider` 로 앱을 감싸고 다크 테마 적용

5. 상세를 Drawer 로 열고 사진을 Carousel 로

### 최종 서비스 적용 여부

동작이 필요한 곳에만 쓰고, 화면의 얼굴이 되는 카드·눈금·배너·지수 게이지는 직접 만든 것을 유지했습니다.
지금 쓰는 것은 Drawer, Carousel, Image, Skeleton, Tag, Select, Empty, Alert, Message, Tooltip,
Button, BackTop, ConfigProvider 입니다. `theme.js` 도 그대로입니다.

### 개인 추가·변경 내용

1. 라이브러리를 전면 채택하지 않았습니다. 기본 컴포넌트를 그대로 깔면 사이트가 라이브러리 데모처럼 보입니다
2. `theme.js` 오버라이드로 캠핑 팔레트를 주입해 직접 만든 부분과 색이 따로 놀지 않게 했습니다
3. 야영장 사진을 Carousel 로 최대 8장까지
4. Skeleton 을 목록·예보·야영장 세 군데에 각각 형태를 맞춰 넣었습니다

### 트러블 슈팅

1. `NCarousel` 은 제 높이가 없습니다. 드로어에 넣었더니 남는 세로를 다 먹어 아래가 밀려났습니다.
   높이를 직접 못 박아야 합니다
2. keyframe 안에서는 `var()` 로 준 `width` 가 해석되지 않습니다. 배점 막대가 계속 0px 이었습니다.
   길이는 요소에 박고 늘어나는 것만 `transform: scaleX()` 로
3. `mix-blend-mode: screen` 을 안쪽 요소에 걸었더니 부모가 `z-index` 로 만든 쌓임 맥락에 갇혔습니다
4. 전면 배너를 만들며 `overflow-x: clip` 을 본문에 걸었더니 배너가 잘렸습니다. `html` 에 걸어야 합니다

## Hands on 9 — Weather Deployment

### 구현 내용

1. ESLint 와 oxlint 를 함께 걸고 규칙 위반 정리
2. Prettier 로 서식 통일
3. API 키를 `.env` 로 옮기고 `.gitignore` 에 넣음
4. `vite build` 로 정적 파일 생성, 화면별 청크 분리 확인

### 최종 서비스 적용 여부

Vercel 에 올렸습니다. `npx eslint .` 오류 0개, `npx prettier --check src/` 통과합니다.

배포하며 가장 크게 바꾼 건 인증키 처리입니다. `VITE_` 접두사를 붙이면 값이 번들에 박혀
개발자 도구에서 그대로 보입니다. 저장소가 공개라 더 그렇습니다. 프런트만으로는 막을 수 없어
서버를 한 겹 뒀습니다.

`api/` 에 서버리스 함수를 두고 브라우저는 `/api/owm/...` 같은 같은 출처 주소만 알게 했습니다.
키는 서버 환경변수에만 있고 함수가 붙여서 원본으로 넘깁니다. 공공데이터포털의 CORS 문제도
같은 함수가 함께 해결합니다.

`createWebHistory` 라서 `/camps` 로 바로 들어오면 404 가 납니다. `vercel.json` 에 SPA fallback 을 뒀습니다.

### 개인 추가·변경 내용

1. 인증키를 브라우저에서 걷어냄 — 서버리스 함수와 그에 맞춘 개발 서버 프록시.
   빌드 산출물과 네트워크 요청 어디에도 키가 남지 않는 것을 확인했습니다
2. 키가 필요 없는 Open-Meteo 도 같은 출처로 넣었습니다. 외부 도메인을 브라우저가 직접 물면
   그 도메인이 막힌 망에서 화면이 통째로 죽습니다
3. `index.html` 정리 — 스캐폴딩 기본값이라 탭 제목이 "Vite App" 이었습니다
4. 안 쓰는 코드 정리 — 부르지 않는 함수와 스토어 액션, 어느 template 에도 없는 CSS 클래스와 토큰

### 트러블 슈팅

1. 배포하니 날씨와 야영장이 전부 안 나왔습니다. 함수를 `api/owm/[...path].js` 캐치올로 뒀는데
   Vercel 이 이걸 한 칸짜리 동적 경로로만 잡습니다. `/api/gocamping/basedList` 는 되고
   `/api/owm/data/2.5/weather` 는 404 였습니다. 함수를 평평하게 두고 원본 경로는
   `vercel.json` 의 rewrite 가 `?path=` 로 실어 보내게 바꿨습니다
2. 다른 컴퓨터에서 열면 지수가 하나도 안 떴습니다. Open-Meteo 만 브라우저가 외부 도메인을
   직접 부르고 있었고, `weatherStore.load` 가 `Promise.all` 이라 그 한 곳이 거부되면 멀쩡히
   받아온 관측값까지 버려졌습니다. 예보도 프록시로 넣고, 실패는 `catch` 로 받아 관측값만이라도
   띄우게 고쳤습니다
3. `.env` 를 확인하려고 셸에서 `set -a; . ./.env` 로 읽었다가 PATH 가 날아가 `curl` 이 사라졌습니다.
   `.env` 안에 셸이 해석할 수 있는 값이 있으면 환경이 통째로 덮어써집니다
